# First desktop editor slice

Status: a working Tauri 2 desktop prototype backed by the real Rust document engine. Native macOS/aarch64 build and launch are verified. Chromium workflows test the same bridge and actual temporary project files. Linux/Windows execution, comprehensive native interaction automation, packaging, and large-document rendering validation remain pending.

The headless multi-project session owner and logical drawing-document ownership are implemented, but this desktop still opens one project at a time. [The implementation task list](workspace-and-sheet-implementation.md) tracks host/bridge/explorer integration and its rework dependencies.

Target architecture has since been corrected to Project → Documents → Sheets, with editing directly on template-backed drawing sheets. The desktop now edits project drawings directly on template-backed sheets, with a separate clipped numeric layout review. Definition editors will be separate workspaces. See [decision 0030](decisions/0030-sheet-first-project-documents.md).

## Start the app

Install the repository's Rust toolchain/components, Node 22.12+, and the appropriate [Tauri system prerequisites](https://v2.tauri.app/start/prerequisites/). Node 25.9.0 was used for the current macOS validation. The frontend and native host each have committed lockfiles.

```sh
cd apps/desktop
npm ci
cargo fetch --locked --manifest-path src-tauri/Cargo.toml
npm run desktop
```

These first dependency-cache setup steps can use the network. Once the required packages are cached, `npm ci --offline` and the offline Cargo checks can run locally. `npm run desktop` starts Vite on loopback port 1420 and the Tauri window. Rust source changes restart the native host; frontend changes reload the webview. Do not rely on a development restart to retain unsaved in-memory work.

To build an embedded-asset debug binary without an installer:

```sh
npm run desktop:build -- --debug
```

It is written under `src-tauri/target/debug/` and runs without a Vite server. This is a native binary build, not an installed/notarized release package. The Tauri host is a separate Cargo project so normal core checks do not require webview libraries.

## Working behavior

- The initial conveyor demonstration is real domain/drawing data, not a static frontend mock. Its pristine state can be replaced or closed; after editing, save protection applies. Save first chooses a new project destination. Existing unobserved files are protected by the document controller.
- Native open/save choosers load validated projects and preserve the original document on failures. Opening another project, closing, or quitting is blocked while changes need saving. Save-as currently refuses unobserved existing destinations, even if a platform chooser offers overwrite. A complete save/discard/cancel workflow remains future work.
- Pages is the default explorer, showing the current project, logical documents and ordered sheets. A sole untouched Drawings package is elided; custom/empty groups remain visible. Use Electrical for the functional/component hierarchy and drawing representations. Header buttons, View menu and command search share registered mode actions. Mode changes retain drawing selection and separate expansion state. Page clicks activate the existing sheet; page right-click opens that sheet's settings. Unfinished tools/actions prevent retargeting. Right-click the project root for Properties and Add new schematic, cover or drawing-list sheets. Properties include three future-sheet template defaults; Apply updates metadata/defaults in one undo operation. Creation reviews a chosen owner, number, title, template and paper, then opens the new page. Schematics create an independent view; cover/list roles have no placed schematic. Document-management controls and multiple project roots remain planned.
- The workspace has fixed explorer/inspector widths, a fixed toolbar/status area, and internal pane scrolling. Errors and long values do not insert layout rows or widen the canvas container. The minimum native window is 960 × 640. Docking, splitter resizing, and saved workspace layouts are not implemented.
- File, Drawing and Library ribbons group the tools in a fixed 96-pixel area, with Drawing selected initially. Quick-access Open/Save/Undo/Redo remain visible. Switch tabs with the pointer or ArrowLeft/Right/Home/End without moving the canvas, clearing selection or cancelling a draft. File and drawing commands use their existing registry paths. Library/Git management controls are visibly planned and disabled; interactive wire placement remains disabled until its tool is integrated.
- SVG renders committed paths, terminal placements, and literal annotations. Drag empty canvas left-to-right to enclose complete objects, or right-to-left to select touched objects. Shift adds marquee results; Escape cancels. Shift-scroll pans horizontally; Ctrl-scroll pans vertically (also on Mac); middle-button drag also pans. Unmodified scroll zooms about the cursor; F fits the active sheet, including blank pages. Select in the drawing or explorer. Shift selects a mixed group. Right-click a drawing object exposes the complete inspector, retaining an existing group; right-click the sheet background opens sheet settings.
- Select terminal anchors, annotations or graphical paths and press M (also in Edit/toolbar/palette) to move a group. Choose the reference origin in the reserved placement strip. Pointer previews come from Rust and include connected routes; terminal/endpoint/midpoint/5 mm grid snaps use a ten-pixel tolerance. Tab cycles targets; hold Alt to suppress. X/Y accept exact integer micrometres and bypass snapping. Apply/Enter or a canvas click commits the acknowledged proposal as one undo operation. Escape/Cancel leaves history unchanged. Invalid proposals disable Apply. Move routes through their anchors; electrical objects have no implicit drawing origin.
- Drag an anchor, annotation or graphical path to move it directly; dragging an already selected object retains the group and the grabbed offset. Release waits for the final Rust preview and commits one undo step. Escape or pointer/focus loss cancels an unfinished drag. Routes move through anchors.
- Press R to preview rotation, or choose Rotate/Mirror from Edit, toolbar or command search. Rotation supports clockwise/anticlockwise quarter turns and 180°; mirror uses a vertical/horizontal axis through the visible pivot. Pivot X/Y start at the first selected origin and accept exact integer micrometres. The pivot marker and full route preview update without edits. Apply/Enter or a canvas click commits one undo step; Escape cancels. Text stays upright. Rotate/mirror connected routes through their anchors. These controls share the reserved tool strip without shifting panes.
- Choose Align or Distribute in Drawing, Edit or command search for selected annotation, graphical path or terminal origins in one view. Align X/Y origins to an exact integer micrometre coordinate; distribute three or more origins evenly along X/Y while retaining the extrema. Connected routes follow their anchors. Review the Rust preview, then Apply/Enter or click the canvas; Escape cancels. Invalid geometry disables Apply but keeps the tool editable. Applying an already-matching arrangement leaves history, redo and the saved checkpoint unchanged. These commands arrange origins; visual-edge alignment and equal edge gaps remain planned.
- Press T (or Edit/toolbar/command search) to create an annotation in the active view. Enter literal text, then position it with the pointer or exact X/Y micrometres. Pointer placement offers the same snap/cycle/Alt-suppression controls as movement while the canvas owns input. Apply/Ctrl+Enter/Cmd+Enter or a canvas click creates one undoable object using the real text creation preset; Escape cancels. The new object becomes selected for Properties. All text editors support line breaks directly: Enter inserts a newline and Ctrl/Cmd+Enter applies. Text properties also have Apply buttons. Annotations/captions render blank lines and indentation, while selection/Fit use the full text block. Live electrical labels remain future work.
- Press P (or Edit/toolbar/command search) to draw a retained graphical path. Click to accept vertices, or use exact X/Y and Add/Enter in a coordinate field. Tab cycles snaps and Alt suppresses them. Backspace/Back removes the last draft vertex. Accepted segments are continuous; the dashed next leg is tentative. Enter on the canvas or Finish commits only accepted vertices as one undo step; Escape cancels the draft. The resulting path is selected for Properties/move/rotate/mirror. This tool uses the graphical stroke creation preset and adds no electrical connections.
- File → Information, File → Project properties… and command search open the same project-information editor. Company name/address, contact engineer, project title/product/client/contract and project issue are literal multiline values carried inside the project. Stable keys identify future sheet variables. Apply is one undoable edit; Cancel and unchanged Apply preserve document history. The editor scrolls its fields internally with fixed Apply/Cancel controls at 960 × 640. Personal/company profiles are managed separately under File → Profiles. The bundled frame resolves eight live fields; custom table/template editing and placeholder placement remain planned. See [sheets and templates](sheets-and-templates.md).
- File → Profiles (also its menu and command search) manages reusable company/contact defaults. Save a named profile outside project history, select fields and Preview import to review old/new project values. Apply import makes one undoable copy, retaining other project fields; empty profile values clear entries only when selected. Close/Escape cancels the proposal. Saving a profile never dirties the project or clears redo. Reload profiles refreshes external changes and discards the profile draft. Files are kept in the native per-user app configuration directory; browser tests use isolated temporary storage. Profile schema v1 remains separate from project persistence. Profile deletion, logos and automatic default selection remain planned.
- Drawing → Sheets (also Edit/menu/search) selects saved template variants and edits literal drawing number/title, optional source view, exact scale terms and paper/source origins. Paper/margin values are read-only projections of the saved variant. Preview/Apply uses a retained revision-bound proposal; Move up/down and Remove sheet are separate undoable commands. Reorder keeps drawing numbers unchanged; removing a sheet retains its source view. Sheet display selects the editable template-backed page. Source-unit tools work directly on it through the inverse placement transform; editing outside paper stays visible for recovery. The numeric review alone is clipped to paper. Sheet cameras persist during the open session; placement/paper changes refit, while metadata changes retain the viewport. Shared views display a warning and edits appear on all placements. With no sheets, use the empty-state Sheets action to review and attach a retained view; cancelling does not dirty the project. One placement per sheet is supported; custom templates, output sets, multiple placements and print/PDF remain planned. See [paper-sheet scope](sheets-and-templates.md).
- Drawing Defaults opens from Drawing, Edit, command search, or Primary+K then S. Edit the project font, positive integer micrometre text height/stroke width, and #rrggbb output colour. Apply changes all four fallbacks in one undoable command. Inherited properties update; object/view/named-style overrides, creation presets and electrical data retain their exact intent. Cancel makes no changes; unchanged Apply preserves redo. Invalid input keeps the dialog open with its draft and a reserved error area. Font requests support multiline text storage, with system-dependent font availability. Creation preset and named-style editors remain planned.
- The inspector uses all applicable core property metadata, including read-only structural fields, mixed values, origins, and applicable/unsupported counts. Text, positive lengths, colours, and eligible coordinate fields have editors. Ctrl/Cmd+Enter or Apply commits text; other editors use Enter. Escape reverts the local input. Editors retain fixed heights with internal scrolling. Complex structural/reference/vertex editors remain pending. Lengths and coordinates are edited in exact integer micrometres, distinct from physical wire attributes.
- Undo/redo, save, Properties, fit, command search, and connection reports use the shared registry/router/dispatcher. Open is a host request through that registry. Primary+O/S/Z, Primary+Shift+Z/P, E, and F are available where applicable. Native text fields and IME composition own their input. Mac uses Command; Windows/Linux profiles use Control. Tools not shipped by this UI are disabled in command search.
- The connection pane derives actual wire endpoints and cable membership from the electrical report. It does not create devices or infer connections from crossing graphics. If the document changes while the pane is open, stale rows are replaced by a refresh prompt without resizing the pane.

An untouched loaded project is clean. Actual edits change its core history/checkpoint, and undo/redo can return to a saved state. A report or selection change does not dirty the document. Exact IDs, revisions, and editor values cross the bridge as strings; only scene display coordinates use floating-point millimetres.

Logical document metadata and ordered sheet IDs are exposed by the bridge, but package creation/rename/transfer controls are not yet in the desktop. The current flat sheet manager preserves owners on property edits/removal undo and rejects cross-document flattened moves. Each package has an exact saved default; sheet review and drawing display resolve its bundled geometry and live fields. Migrated starter layouts preserve the original eight fields. Cell overflow is clipped/marked with full-value tooltips, and insufficient paper shows a diagnostic. The editable sheet canvas and explicit per-view attachment are implemented. Custom templates and bulk wrapping remain subsequent slices. New schematic creation now creates its own independent source view.

## Local verification

Install the pinned browser test runtime once:

```sh
cd apps/desktop
npm exec -- playwright install chromium
```

Then from the repository root:

```sh
cargo xtask full
cargo xtask ui
cargo xtask desktop
```

`full` includes the headless bridge contracts and remains independent of Node/Tauri. `ui` checks bridge tests, Prettier, TypeScript/build, and forty-two browser workflows. It starts an isolated Rust harness on port 3838 and Vite on 1421, operating on a temporary approved project. It does not mock the electrical model and does not contact GitHub. Screenshots are written to ignored `target/ui/`. The harness is an example/test program, not a production HTTP service; it binds loopback, accepts bounded JSON requests only from the known local frontend origins, and exposes no arbitrary file-open endpoint. Native desktop uses IPC instead.

`desktop` checks frontend formatting/build and native Rust formatting/Clippy with the separate locked host manifest. It needs the platform's webview development dependencies. A native launch smoke test separately confirmed that the macOS webview invokes the Rust controller; browser tests do not prove native dialog, accessibility, font, or keyboard behavior.

The browser workflows also cover cursor-centred zoom, modifier pan axes, directional/additive marquee selection, painted path/cap bounds, preserved drag offsets/groups, delayed final preview release, and gesture cancellation. Native hardware trackpad/mouse behavior remains unverified. The workflows cover actual property edit/save/undo/redo, mixed applicability, protected typing, right-click selection, pan/zoom/fit, long and markup-like values, error/focus retention, window resizing, report values, and external-save conflicts. The Rust bridge tests cover stale/foreign contexts, malformed input, exact large numeric values and IDs, full union inspection, guarded lifecycle failures, shared input replay/resynchronization, closed move proposal invalidation/cancellation, exact preview/commit/history agreement, and shortcut timing across frontend reloads.

## Boundaries and next steps

This is a bounded interaction prototype. Wire/symbol placement, sub-element selection, font measurement/export parity, library/default editors, full native menu integration, pane layout preferences, and coherent cable overview/detailed sheet navigation remain planned. SVG terminal captions are derived view feedback; they are not persisted live connection-label templates. The SVG scene is currently a complete projection and has no virtualization or large-view capacity claim. A different renderer/framework can replace it behind the bridge as measured workloads justify.

Project schema v9 adds logical drawing-document metadata and membership over v8 paper sheets; v2–v8 load with a deterministic Drawings package and preserve existing source records, upgrading only on explicit save. User selection, viewport, pane state, bridge input IDs, and transient messages are not written to project files. See [decision 0017](decisions/0017-first-desktop-slice.md), [move proposal lifecycle](decisions/0018-desktop-move-proposals.md), [pointer controls](decisions/0019-cad-pointer-controls.md), [orthogonal transforms](decisions/0020-desktop-orthogonal-transforms.md), [annotation placement](decisions/0021-desktop-annotation-placement.md), [unified multiline text](decisions/0022-unified-multiline-text.md), [retained graphical path placement](decisions/0023-retained-graphical-path-placement.md), and [fixed ribbons](decisions/0024-fixed-tool-ribbons.md).

Drawing-list pages contain generated number/title links to stable sheet identities. Natural number sorting puts 2 before 10. Additional physical list pages consume subsequent rows; if capacity is insufficient, the heading/badge reports remaining drawings. Add another list page explicitly. Links work by pointer across the full row and by Enter, with normal sheet-switch guards. PDF export and PDF link annotations remain future work; the current implementation supplies their stable targets.

Project body storage was introduced in v12 ([decision 0039](decisions/0039-project-template-bundles-and-legacy-capture.md)); saved-reference assignment follows in v13 as described below.

Saved-template assignment now uses schema v13 in the desktop. Legacy projects migrate in memory before the clean checkpoint, preserving exact layouts and inherited paper variants; source files change only on explicit Save. Sheet creation/settings and Project Properties select saved project-bundled variants. Paper/margin values are read-only, and inline paper presets/orientation authoring has been removed. Source placement and scale remain editable through Preview/Apply. Tiny legacy sheets retain their diagnostic frame and can be edited/recovered, while new assignments require an eligible saved revision. The first independent Libraries editor is now available, as described below. See [decision 0040](decisions/0040-saved-template-assignments-and-inherited-variants.md). The browser suite now contains 42 workflows.


Libraries → Drawing templates opens a separate template editor with its own Template ribbon, placeholder preview and properties. New/Open/Save revision, independent Undo/Redo, Reload library, explicit Add saved revision to project, Close and Discard are available. Select/right-click a title-block cell to edit its multiline caption and literal/variable runs. Apply commits one validated proposal; Revert restores applied values. Paper/margins/content bounds use exact integer micrometres. Numeric table geometry tools are described below; drag-based table authoring and verified ISO/ANSI presets remain planned.

Template saves publish to `drawing-templates.json` in the native app configuration directory. Project import is explicit and undoable, leaving existing sheet/default pins unchanged. Unsaved drafts and pending fields participate in close/quit guards; close or discard the editor before opening/saving-as a project. Unapplied fields are transient and have no crash recovery. Browser tests use a temporary library beside the test project (`ECAD_UI_TEMPLATES` can override it). See [decision 0041](decisions/0041-independent-template-editor.md) for boundaries and remaining work.


The Template ribbon now includes Resize, Split, Merge and Boundary tools with captured numeric review dialogs. They operate on retained table partitions, support unequal subdivisions and spans, preserve exact undo/redo and reject geometry outside the paper margins. Merge shows current cells and an explicit content policy; Combine retains captions and unresolved variables in reading order. The properties editor can add/remove text/variable runs in new blank cells. Cancel retains draft geometry and redo; pending table fields are protected by native dirty guards. Table insertion/removal, drag handles, verified ISO/ANSI profiles and automatic revision adoption remain future work. See [decision 0042](decisions/0042-structured-template-table-edits.md).


For direct title-block editing, drag across cell interiors to select a range; merged cells are selected in full. Merge opens with the range preselected. Selected tables show a move grip, draggable cell/outer edges, and contextual plus buttons for rows and columns. The plus buttons keep the bottom/right edge fixed; cells spanning an insertion boundary extend and other intervals receive blank editable cells. Palette actions also expose numeric row/column insertion. Drags use validated previews and commit one undo operation on release; Escape cancels, including in-flight previews. Invalid geometry leaves the original table unchanged. See [decision 0043](decisions/0043-direct-template-table-interaction.md).


Template properties now includes General margin (µm), which sets all four sides together and shows Mixed for individual overrides. Editing it checks the visible Fit layout inside margins option: out-of-interior tables move only as needed, their cell sizes stay unchanged, and the content region is intersected with the new border. Impossible fits retain the fields for correction; Undo restores the full layout. Table movement and outer-edge resizing snap within eight screen pixels of the margin border, with green preview guides. Hold Alt to bypass; numeric dialogs remain exact. These are placement snaps, not persistent attachments. See [decision 0044](decisions/0044-template-margin-controls-and-snapping.md).

### Template artwork

In the template editor choose **Artwork** on the Template ribbon (also available in command search). Add text, a line/polyline, rectangle or ellipse, edit paper coordinates and appearance, then **Apply properties**. Expand an artwork item for its fields, or select it in the preview/explorer. Add literal or variable runs using the same controls as table cells. Text is multiline; overflowing text is clipped with a marker and full-value tooltip. Templates show variable placeholders; assigned project sheets resolve their own values.

Artwork changes share template Undo/Redo, Revert fields and Save revision. Artwork may sit in margins and stays fixed when table margin fitting runs. Vector authoring supports exact coordinates/local point lists and the pointer tools below. Imported logos/images are not implemented yet.

### Pointer artwork tools

The Template ribbon's **Draw** group places text boxes, lines, rectangles and ellipses: choose a tool, then drag between two paper positions. Reverse drags are supported, including horizontal/vertical lines. Text starts as `Text`; edit multiline text or add variables through its properties. Drag an existing object to move it whole, or right-click to open its properties. **Escape** cancels; each changed gesture is one undo step. Click-only movement preserves redo.

Placement previews are checked by Rust and commit the final release coordinate. Out-of-paper or collapsed geometry is rejected. Artwork pointer coordinates are currently unsnapped. Images, multi-click polyline drawing and pointer resize/vertex handles remain future work; numeric geometry/local-point editing remains available.

### Contextual template selection

The inspector now follows the active cell range or artwork object; blank-paper clicks and canvas Escape clear selection and return to paper properties. Artwork selection clears table handles. Table interiors receive hits ahead of background artwork. The explorer and right-click use the same selected target. Contextual fields complete on Enter, Tab/blur or choice changes; multiline fields use Ctrl/Cmd+Enter and retain plain Enter for newlines. Pointer selection changes finish valid fields on the original target first. Invalid input remains visible for correction; Escape reverts pending fields. Apply/Revert remain fallback controls, and numeric artwork management still uses explicit Apply. A pointer that finishes an edit selects its destination without starting a drag. The existing Artwork management action is retained for numeric insertion while the simplified Insert workflow is implemented. See the [integration roadmap](contextual-editor-integration.md) for the staged replacement.


### Contextual Split/Merge and paper presets

Select a cell or vertically aligned contiguous stack, then choose **Split**; only row/column counts are required. All selected cells split in one undo step. **Merge** is available only for a rectangular cell selection; the top-left identity survives. Content handling appears only when more than one selected cell contains captions or text. The final Apply confirms the merge. No table/cell identifiers or survivor selectors are needed. Ribbon and palette eligibility comes from Rust and dispatch checks the same captured target.

Paper properties show **Paper family**, **Paper size**, **Orientation** and **General margin**. Presets cover ISO A0–A5 and US Letter/Legal/Tabloid/ANSI C–E. **Advanced paper settings** retains exact custom dimensions, individual margins, content bounds and fit behavior. Preset/orientation edits never scale cells or artwork; invalid fits remain editable. Custom values survive save/reopen. These are dimension presets, not verified standard margin profiles. See [decision 0047](decisions/0047-contextual-table-actions-and-paper-presets.md).


### Click placement and shared previews

Template **Line**, **Rectangle** and **Ellipse** tools accept a start click and a finish click, with a visible anchor and hovering preview. Press-drag-release placement still works. Escape cancels; the final point controls the result even while an older preview is loading. Invalid final geometry creates no object. Whole-artwork movement uses dragging; text creation now follows the inline workflow below.

Template gestures and schematic annotations now share preview scheduling. A schematic text finish click or Ctrl/Cmd+Enter waits for the latest text/position preview; invalid final values remain editable. Tool cancellation suppresses delayed replies from the old frontend session. Each successful placement remains one undo operation. Inline template text creation is described below; shared appearance controls remain planned. See [decision 0048](decisions/0048-shared-preview-queue-and-click-placement.md).


### Inline template text creation

Choose **Draw template text**, then click the starting point. A canvas-local editor opens with multiline literal/variable controls; use **Add text content** to append runs and choose **Variable** for a typed placeholder. **Place text** or Ctrl/Cmd+Enter creates the complete object once; Enter inserts newlines, and Escape/**Cancel text** leaves no object or undo entry. Invalid text remains editable. The existing IME protections apply.

Click placement starts with a 60 × 20 mm box limited by the remaining paper. Drag a box instead when a specific extent is needed; both workflows edit contents before committing. The floating editor stays inside the canvas at smaller window sizes. Text appearance and exact box dimensions remain available in the contextual inspector after placement. Overflow uses the existing clipping/marker policy. Library previews show placeholders; sheet values resolve only in their project context. See [decision 0049](decisions/0049-inline-template-text-placement.md).
