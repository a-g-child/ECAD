# 0057: Row-specific table layout and fitted contextual columns

The Template ribbon's Resize button becomes **Layout**, opening a row-count selector and one column-count input per row. This edits the retained table partition inside its existing bounds. Pointer sizing and the registered numeric Resize action remain available; numeric Resize is accessible through command search.

The domain owns repartitioning. Rows are grouped by cell top edge and ordered top to bottom; cells are ordered left to right. Surviving row/column positions retain identities, captions, typed bindings and both text styles. New cells have fresh identities and blank/default-styled content. Surplus rightmost cells/bottom rows are removed only after explicit acknowledgement in the dialog. The bridge enforces acknowledgement, positive counts, a 4096-cell operation budget and the original editor revision. One template edit stores the complete before/after layout for exact undo/redo; no persistence change is required.

Unchanged counts are an exact no-op, preserving unequal widths, spans, presentation order and redo. Changing row count distributes row heights evenly. Otherwise existing row top edges remain. Changed column counts distribute that row's widths evenly; unchanged complete rows retain their widths. When counts change on a table containing vertical spans, cells belong to their starting row and become ordinary row cells, without duplicating content. The dialog explains this normalization. Integer boundary division retains exact outer bounds and rejects collapsed cells.

The row selector offers 1–64 rows for normal template authoring and preserves larger imported row counts as an additional option. The core independently bounds the total output cells. Input changes remain transient until Apply; Cancel releases the existing pending-edit guard without creating history.

Contextual **+ column** previously grew the table by the selected cell width, rejecting wide/repeated insertions outside the margins. It now inserts through the existing span-aware partition operation and scales horizontal boundaries back into the original table width. Existing cells and spans survive, blank cells follow adjacent divisions, and both outer edges stay fixed. Contextual row insertion and explicit numeric band insertion retain their existing growth-anchor behavior. The tooltip distinguishes fitted columns from growing rows. Plus controls are centred beside the actual selected range, including cells away from the table origin.
