# 0033: Pinned bundled sheet frame and derived drawing information

Status: implemented as the first frame slice. The subsequent [editable-sheet decision](0034-editable-sheet-workspace.md) replaces the Model view/read-only paper arrangement used during this slice.

Every logical drawing document has a mandatory default_template. The first supported value is the immutable bundled standard-v1: a border at the paper margins and an eight-cell, two-column, four-row title block anchored at the bottom right. The block measures 180 × 40 mm independently of drawing-view origin or scale. Changing its geometry later requires a new template identity. Custom project-bundled revisions and per-sheet overrides are future work, not arbitrary strings accepted by this implementation.

Schema v10 stores the template default explicitly. Separate strict v9/v10 document records share the root conversion without allowing v10 fields through the v9 decoder. V2–v9 receive standard-v1 deterministically; v1 remains an explicit identity migration. Legacy IDs, geometry, styles, electrical content and shared/unplaced views are retained. Unknown, null and missing v10 template values fail loading. Existing document commands/history include the default as part of the exact document value.

Frame geometry is a domain read projection in integer paper micrometres. Typed fields resolve company.name, project.title, document.title, sheet.title, document.number, sheet.number, document.revision and owner-local sheet ordinal/count. This count describes the owning document, not a future output subset. Company values come from portable project metadata, never the current machine's profile. Missing optional metadata remains absent. Literal multiline values are preserved and are not formulas, HTML or electrical objects.

The frame inherits font, value height, stroke width and colour from project drawing fallbacks; source view styles and scale do not affect its physical dimensions. Captions have an explicit standard-v1 height of 1.5 mm and cells reserve their own caption strip/inset. In the browser, values exceeding the cell are clipped and marked with a corner indicator and a full-value tooltip. Text never silently shrinks. These are current-renderer bounds checks, not output/font parity validation. Required fields, wrapping, logos, output preflight and custom structured cell editing remain future slices.

A valid sheet may be smaller than the standard table. Keep its border, omit the table and return a title-block-too-small diagnostic; show this in the sheet review and paper badge. Do not invalidate old paper records or manufacture overlapping/zero-sized cells. Numeric sheet preview resolves its frame from the validated candidate so titles and counts match the proposed state; it retains the original revision and changes no live project data. A later metadata edit invalidates commit through the normal revision guard.

## Evidence and revisit conditions

Adapter workflows cover live bindings/history/save/reopen, exact physical bounds at minimum/maximum sizes, extreme source placements/scales, strict migration and candidate-preview counts. Bridge tests compare reviewed and committed frame DTOs and live metadata undo. Browser workflows cover both paper surfaces, literal multiline values, overflow, metadata refresh/undo, small-sheet diagnostics and stable pane bounds. Local macOS/aarch64 validation passed: cargo xtask full (324 behavior tests and two doctests), cargo xtask ui (32 browser workflows), cargo xtask desktop and embedded-asset native debug build/launch with the webview connected to Rust; native interaction and font/output parity on Windows/Linux remain unverified.

Revisit when implementing custom table editing, template adoption, output/preflight or another renderer. The immediate next slice replaces the separate model/paper surfaces with direct editing on these template-backed sheets, including reviewed wrapping of unplaced views and explicit shared-view behavior.
